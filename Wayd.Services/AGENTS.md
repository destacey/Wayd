# AGENTS.md — Domain services

The root [AGENTS.md](../AGENTS.md) applies here too. This file holds the rules for list queries, Demand Management's authorization, and domain events, which every module raises and consumes. Each rule links to its full explanation in [domain-events.mdx](../docs/contributing/domain-events.mdx) — **read the linked section before adding, changing, or consuming an event.**

## List Queries

- **A list query ends its order on a unique key** (`Key` or `Id` last), never on whatever order the database returns. The hosted MCP server pages a list tool's answer with an `offset` over several calls, so an unstable order repeats and skips records between them. [Result size](../docs/contributing/mcp-server.mdx#the-hosted-endpoint)

## Demand Management Authorization

- **Acting on an intake request is decided by desk role alone**: Agent or Desk Admin on its desk (`IntakeRequestReader.IsAgentOn` / `IsDeskAdminOn`, read from `IntakeDeskMember`; an inactive employee is a member of nothing). Its endpoints carry `[Authorize]` only, so the handler is the whole gate. `Permissions.IntakeRequests.View` only widens browsing; `Administer` is Desk Admin on every desk. Never add a resource permission beside a desk role. [Permission-based vs membership-based](../docs/contributing/architecture.mdx#permission-based-vs-membership-based-authorization)

## Domain Events

- **Every event is audited for free.** `SaveChanges` captures every drained event into `ActivityLogs`, and an event nobody subscribes to is a no-op, so a new event needs no handler. Add it to `DurableEventRoutes` only when a consumer needs asynchronous delivery.
- **Name it for what happened**, matching the method that raises it (`ChangeLifecycle` → `ProjectLifecycleChangedEvent`). Descriptive edits are a `DetailsUpdated` event, each transition its own event; a bare `XxxUpdatedEvent` is never right. Implement the module's marker interface (`IPpmEvent`, `IProductManagementEvent`). [Designing an event](../docs/contributing/domain-events.mdx#designing-an-event)
- **Declare its category.** Derive from `DomainEvent<TSelf>`, implement `IDomainEventDescriptor`, and pick `ActivityCategory` by what happened, not by the words in the name. [Categorising an entry](../docs/contributing/domain-events.mdx#categorising-an-entry)
- **The payload is the change plus identity**, starting from `Id`/`Key`; each field must pass the four ordered tests. People are ids, never names or emails. Never ship the whole record to a copy — the one exception is a baseline. `DomainEventConventionTests` enforces naming, serializability, and no personal data. [Designing an event](../docs/contributing/domain-events.mdx#designing-an-event), [Baselining](../docs/contributing/domain-events.mdx#baselining-a-record-that-predates-its-events)
- **One fact, one event.** A fact about another record implements `IRelatedAggregateEvent` instead of raising a mirror event; adopting it on an existing event needs a backfill, and only records read under the same permission may be related. [More than one record](../docs/contributing/domain-events.mdx#an-event-about-more-than-one-record)
- **`AddDomainEvent` is the only way to raise, and nothing collapses events.** Never reintroduce "supersede the pending event". [Every raise is a fact](../docs/contributing/domain-events.mdx#every-raise-is-a-fact-nothing-collapses-them)
- **Raise only on a real change, comparing after assignment** — setters normalise (`"Atlas "` → `"Atlas"`), so comparing against the arguments reports false changes. [The aggregate decides](../docs/contributing/domain-events.mdx#the-aggregate-decides-whether-anything-changed)
- **An evented aggregate changes only through events**: every state-changing public method raises, and nothing writes its table set-based (`ExecuteUpdate`, `ExecuteDelete`, raw SQL, a data-fix migration). `EventCoverageTests` enforces it. [Only through events](../docs/contributing/domain-events.mdx#an-evented-aggregate-changes-only-through-events)
- **A change carries both ends** (`From*`/`To*`, `PreviousDateRange`, previous id and name); collections carry `Added`/`Removed` and the resulting set. When the previous value lives on a navigation, `.Include` it and have the aggregate throw if it was not loaded. Load the incoming record tracked and set the id and navigation together: an untracked instance reached through a navigation on a `ValueGeneratedNever` key is inserted on save. Both need a Testcontainers test (`SavedEntityRecorder`). [Both ends](../docs/contributing/domain-events.mdx#a-change-carries-both-ends)
- **A post-persistence creation event captures its payload at creation**, reading only `Key` inside the deferred action — imports create and then move a record before the first save. [Recorded as created](../docs/contributing/domain-events.mdx#a-creation-event-records-the-record-as-created)
- **A durable consumer sees events late, twice, and out of order.** A module's copy of another's record uses per-group watermarks decided by its `Apply*` methods, builds a missing copy stamped with the triggering event's timestamp, and keeps the `rowversion` from `ConfigureReplicaTracking`. [Consuming an event](../docs/contributing/domain-events.mdx#consuming-an-event)
- **An event about a durable record shares that record's id** as its `EventId`, so a backfill replaying old records stays idempotent. [Sharing an id](../docs/contributing/domain-events.mdx#sharing-an-id-with-the-record-a-transition-writes)
- **Version every event explicitly** (`base(actor, "1.0")`). A compatible change (a new field whose `default` is valid and unambiguous) bumps the minor; a breaking change is a new type at the next major (`ProjectReparentedEventV2`, `"2.0"`); the superseded type is marked `[Obsolete]` and never renamed or deleted. `DomainEventVersioningTests` enforces it. [Versioning](../docs/contributing/domain-events.mdx#versioning-an-event)
