# MCP Server

Wayd provides an [MCP (Model Context Protocol)](https://modelcontextprotocol.io) server that lets AI assistants like Claude interact directly with your Wayd instance. The MCP server exposes Wayd's API as structured tools that AI agents can call to read and manage your delivery data.

**Package:** [`@wayd/mcp`](https://www.npmjs.com/package/@wayd/mcp)

## Prerequisites

There are two ways to connect: the [hosted endpoint](#hosted-endpoint-preview), which the Wayd API serves itself, and the [npm package](#setup), which runs on your machine.

- **Hosted endpoint:** a Wayd instance with the **MCP Server** feature flag on, and an assistant that connects to remote MCP servers over HTTP. You can [sign in](#connecting-with-sign-in) with your Wayd account, so no token is needed, or [use a Personal Access Token](#connecting-with-a-personal-access-token).
- **npm package:** a running Wayd instance, a **[Personal Access Token (PAT)](./your-profile.mdx#personal-access-tokens)** created from your profile page, and **Node.js 22+** installed on your machine.

## Hosted Endpoint (Preview)

The Wayd API also serves MCP itself, at `/mcp` on the API's address, using Streamable HTTP. It offers the same tools under the same names as the npm package, so skills and prompts written for one work with the other, and it needs no Node.js on your machine. It also offers [tools the package lacks](#hosted-only-tools): partial updates that change only the fields you name, single-call evidence reads for health checks, and whole areas the package never covered, such as work items and sprints, employees, team membership and capacity, risks, and planning poker. Each of the [agent skills](#agent-skills) is served there without installing it, two ways: as an MCP prompt named after the skill (`wayd-ppm`, `wayd-pi`, …) that you can pick in a client that lists prompts, and through a skills tool, which the assistant calls on its own. Every tool's description names the skill for its area, so an assistant connected to the hosted endpoint is pointed to that guidance whichever toolsets you chose; whether it reads it is up to the assistant. The npm package will be retired a few weeks after the hosted endpoint is generally available.

An administrator turns it on with the **MCP Server** feature flag (**Settings > System > Feature Flags**); while the flag is off, `/mcp` answers 404. Connect in one of two ways:

- **[Sign in](#connecting-with-sign-in)** with your Wayd account and approve the assistant. Nothing to create, copy or store, and you can disconnect it from your profile at any time. Use this whenever your assistant supports it.
- **[A Personal Access Token](#connecting-with-a-personal-access-token)** in the `x-api-key` header, for an assistant that cannot sign in or a script that runs unattended.

### Connecting with Sign-In

Give your assistant the `/mcp` address and nothing else: no token and no headers. On its first call Wayd answers that you need to sign in, and the assistant opens Wayd in your browser.

Claude Code — add the server, then authenticate from a session:

```bash
claude mcp add --transport http wayd https://your-wayd-api.com/mcp
```

In Claude Code, run `/mcp`, choose **wayd**, and choose **Authenticate**. Or put it in `.mcp.json` without a `headers` block:

```json
{
    "mcpServers": {
        "wayd": {
            "type": "http",
            "url": "https://your-wayd-api.com/mcp"
        }
    }
}
```

VS Code (`.vscode/mcp.json`):

```json
{
    "servers": {
        "wayd": {
            "type": "http",
            "url": "https://your-wayd-api.com/mcp"
        }
    }
}
```

claude.ai, ChatGPT and other hosted assistants: add a custom connector and give it the `/mcp` address. They cannot send a personal access token, so signing in is the only way they connect.

When Wayd opens:

1. Sign in, if you are not already. You come back to the request afterwards.
2. Read the **connection request**. It names the site the application belongs to — that is what identifies it — and the name the application gives itself, which is only its own claim. It also says where you will be sent afterwards, and warns you if that is a different site from the application's.
3. Choose the application's **access**. An application that asks for full access can be given it, or limited to **Read-only access**; one that asks only to read cannot be given more.
4. Choose **Approve** to let the application use Wayd as you, or **Deny** to refuse. Either way you are sent back to the application.

With **Full access**, an approved application can do anything your account can, with all of your permissions. With **Read-only access** it can view, search and export what your account can see, and change nothing: Wayd offers it only the read-only tools, and refuses any change it attempts. Neither gives it a permission your account lacks. It appears as a [connected application](./your-profile.mdx#connected-applications) on the **Sessions** tab of your profile, where you can disconnect it at any time. A request you leave unanswered expires after ten minutes; start again from the application.

A change an application makes through Wayd's tools is recorded as yours, and the [Activity](../user-guide/activity-log.mdx) of the record it changed names the application it was made through.

The assistant keeps you signed in and renews its access by itself. If it stops working, sign in again from the assistant (in Claude Code, `/mcp` again).

An assistant can sign in only if it identifies itself the way current MCP clients do, with a Client ID Metadata Document: a public web address describing the assistant. Wayd does not support the older dynamic client registration. If an assistant cannot complete sign-in, connect it with a personal access token instead.

### Connecting with a Personal Access Token

Send a [Personal Access Token](./your-profile.mdx#personal-access-tokens) in the `x-api-key` header. The assistant then skips sign-in and acts with the token's access until you revoke it.

Claude Code (`.mcp.json`):

```json
{
    "mcpServers": {
        "wayd": {
            "type": "http",
            "url": "https://your-wayd-api.com/mcp",
            "headers": {
                "x-api-key": "your-personal-access-token"
            }
        }
    }
}
```

VS Code / Cursor (`.vscode/mcp.json`):

```json
{
    "inputs": [
        {
            "id": "waydApiKey",
            "description": "Wayd API key (Personal Access Token)",
            "type": "promptString",
            "password": true
        }
    ],
    "servers": {
        "wayd": {
            "type": "http",
            "url": "https://your-wayd-api.com/mcp",
            "headers": {
                "x-api-key": "${input:waydApiKey}"
            }
        }
    }
}
```

### Choosing Tools

Every tool's description is loaded into the conversation before any work starts, and with more than 500 tools across every toolset that is a large part of an assistant's context. Ask for only the tools your work needs by naming toolsets, and add read-only mode for an assistant that should look but never change anything.

| Toolset        | Tools                                                                                                     |
| -------------- | --------------------------------------------------------------------------------------------------------- |
| `ppm`          | Portfolios, programs, projects, tasks, project lifecycles, strategic initiatives, expenditure categories |
| `planning`     | Planning intervals, roadmaps, story maps, poker sessions, estimation scales                               |
| `products`     | Products, product types, tag categories                                                                   |
| `delivery`     | Versions, releases, release packages, deployments, environments, metrics                                  |
| `teams`        | Teams, teams of teams, users                                                                              |
| `organization` | Employees, holiday calendars, team member roles, team types, risks                                        |
| `work`         | Workspaces, work items, sprints, work processes, work types and statuses                                  |
| `imports`      | Checking, applying and following CSV imports                                                              |

Choose them on the URL, or in headers if your client sends them:

| Query parameter                 | Header                             | Effect                                                                |
| ------------------------------- | ---------------------------------- | --------------------------------------------------------------------- |
| `toolsets=ppm,planning`         | `X-MCP-Toolsets: ppm,planning`     | Only those toolsets. Leave it out, or name `all`, for every toolset.  |
| `readonly=true`                 | `X-MCP-Readonly: true`             | Only tools that read; every create, update and delete is left out.    |

The query parameter wins when both are sent. An unknown toolset name is refused with 400 rather than ignored, so a typo does not quietly leave you without tools. A tool outside the selection cannot be called either, so read-only mode holds even against an assistant that knows a write tool's name.

```json
{
    "mcpServers": {
        "wayd-planning": {
            "type": "http",
            "url": "https://your-wayd-api.com/mcp?toolsets=planning,teams&readonly=true"
        }
    }
}
```

Hosted assistants that sign in cannot send headers, so give them the selection on the URL. With a personal access token, add its `headers` block as usual.

Read-only mode limits which tools are offered, not what your account may do. For a guarantee, connect with read-only access: approve the assistant with **Read-only access** when you [sign in](#connecting-with-sign-in), or use a [read-only personal access token](./your-profile.mdx#creating-a-token). Wayd then refuses any change, whatever the assistant tries, and offers only the read-only tools without being asked.

The skills tool, `Skills_Get`, the skill prompts and the `Me_*` tools are offered on every connection, whatever toolsets you chose; read-only mode keeps all of them except the ones that change something: `Me_Follow`, `Me_Unfollow`, the three that mark notifications read, and the four that mute and unmute.

### Large Results

A tool's answer is capped at about 20,000 tokens, so one call over a large project cannot fill the conversation. A list longer than that keeps its first items and says which ones it is showing, such as items 1–74 of 843. Tools whose answer is a list take an `offset` argument, and the note gives the value that continues it, so the assistant can read the rest a part at a time. A tool whose answer is one record holding a list, such as a summary with its work items, takes no `offset`; the assistant narrows it with the tool's filters (a status, a portfolio, a team) instead.

## Setup

### Claude Desktop

Add the following to your Claude Desktop configuration file:

- **macOS:** `~/Library/Application Support/Claude/claude_desktop_config.json`
- **Windows:** `%APPDATA%\Claude\claude_desktop_config.json`

```json
{
    "mcpServers": {
        "wayd": {
            "command": "npx",
            "args": ["-y", "@wayd/mcp"],
            "env": {
                "WAYD_API_BASE_URL": "https://your-wayd-instance.com",
                "WAYD_API_KEY": "your-personal-access-token"
            }
        }
    }
}
```

### Claude Code

Add a `.mcp.json` file to your project root:

```json
{
    "mcpServers": {
        "wayd": {
            "command": "npx",
            "args": ["-y", "@wayd/mcp"],
            "env": {
                "WAYD_API_BASE_URL": "https://your-wayd-instance.com",
                "WAYD_API_KEY": "your-personal-access-token"
            }
        }
    }
}
```

Or set environment variables in your shell and omit the `env` block:

```bash
export WAYD_API_BASE_URL="https://your-wayd-instance.com"
export WAYD_API_KEY="your-personal-access-token"
```

### VS Code / Cursor

Add to your `.vscode/mcp.json` or workspace settings:

```json
{
    "inputs": [
        {
            "id": "waydBaseUrl",
            "description": "Wayd API base URL",
            "type": "promptString"
        },
        {
            "id": "waydApiKey",
            "description": "Wayd API key (Personal Access Token)",
            "type": "promptString",
            "password": true
        }
    ],
    "servers": {
        "wayd": {
            "type": "stdio",
            "command": "npx",
            "args": [
                "-y",
                "@wayd/mcp",
                "--base-url",
                "${input:waydBaseUrl}",
                "--api-key",
                "${input:waydApiKey}"
            ]
        }
    }
}
```

## Configuration

The MCP server accepts configuration via environment variables or CLI arguments:

| Environment Variable | CLI Argument | Description                                                             |
| -------------------- | ------------ | ----------------------------------------------------------------------- |
| `WAYD_API_BASE_URL`  | `--base-url` | The base URL of your Wayd API instance                                  |
| `WAYD_API_KEY`       | `--api-key`  | Your [Personal Access Token](./your-profile.mdx#personal-access-tokens) |

CLI arguments take precedence over environment variables.

## Agent Skills

For Claude Code users, twelve pre-built skills provide guided workflows:

- **`/wayd-ppm`** — Portfolio, program, project, and strategic initiative operations, including scoring, health checks, status changes, and tasks
- **`/wayd-pi`** — Planning intervals, iterations, objectives, and risks
- **`/wayd-products`** — The product catalog, plus the product types and tag axes it is built from
- **`/wayd-delivery`** — Releases, versions, release packages, deployments, environments, and delivery metrics
- **`/wayd-roadmaps`** — Roadmap exploration with activities and milestones
- **`/wayd-story-maps`** — Story map analysis and management with goals, steps, tasks, swim lanes, and personas
- **`/wayd-teams`** — Team lookup and resolving team names to IDs, backlog health, team work distribution reports, and (on the hosted endpoint) managing teams, members, capacity, holiday calendars and risks
- **`/wayd-users`** — User lookup and resolving names to UUIDs for assignees and project roles
- **`/wayd-employees`** — Employees, their managers and direct reports, and time away (hosted endpoint only)
- **`/wayd-work`** — Workspaces, work items, sprints, and the work processes, types and statuses behind them (hosted endpoint only, apart from work item forecasts)
- **`/wayd-estimation`** — Planning poker sessions and estimation scales (hosted endpoint only)
- **`/wayd-imports`** — Loading CSV data: writing a file, checking it with a preflight, importing it, and following import runs

Install the skills:

```bash
npx skills add destacey/wayd
```

## Available Tools

Most records expose an **activity history**: every recorded change, newest first, with who made it and what the value was before and after. A record that existed before Wayd began tracking its changes starts with a baseline entry showing what it looked like at that point. Some changes are listed on more than one record: moving a product under a new parent also appears in the history of both parents, marked as related and naming the product it was made on.

Dependencies are **rolled up**: a product line's list includes its services' links to anything outside it. Strength has no default — hard if the product stops working without the other, soft if it only degrades — and a dependency that stopped should be **ended, not removed**, so the record of when it held survives.

Three behaviours worth knowing. Tagging an axis that only allows one value **silently replaces** the existing tag rather than refusing. Deleting a product is a **hard delete**, refused while anything depends on it. And seeded system types and axes **cannot be edited or deleted, but can be deactivated** — so an organization can hide a type it doesn't use. Individual tags inside a seeded axis are the exception: they can't be deactivated either, so retire the whole axis instead.

Environments are **retired rather than deleted**, because historical deployments still point at them — deleting one takes every deployment into it along. ## Changes That Ask First

Most tools only read data. The ones that change something a colleague relies on — changing a record's status, updating a portfolio, program, or project, deleting anything, or importing, stopping, or re-running an import — are flagged so your AI assistant asks for confirmation before running them.

Whether you actually see a prompt depends on the assistant you're using: the flag is a signal, and clients decide how to honour it. Your permissions are always enforced by Wayd itself regardless of what any client does.

Two behaviours worth knowing before you approve one:

- **Updates replace the whole record.** Anything not included in an update is cleared rather than left alone. This matters most for people: sponsors, owners, managers, and members are replaced as a set, so an update must carry the full team to keep it. Your assistant is instructed to read a record before updating it and pass back everything that should stay the same.
- **Activating a portfolio sets its start date to today, and closing it sets its end date to today.** Neither can be backdated, so avoid using them to tidy up a portfolio that really started or ended earlier.

Deleting a portfolio, program, project, or strategic initiative isn't available through the MCP server at all.

## Security

Whichever way you connect, the assistant acts as you, with your permissions — it can only access what you can access. Read-only access narrows that further: the assistant can read what you can, and change nothing.

- **Signed in:** nothing is stored in your configuration. Disconnect an assistant from the **Sessions** tab of your [profile](./your-profile.mdx#connected-applications) and it loses access at once.
- **Personal access token:** store it securely, never commit it to version control, and prefer environment variables or a client's password prompt over hardcoding it in config files. Revoke it from your [profile page](./your-profile.mdx#personal-access-tokens) if it is exposed.

Changing a portfolio, program, or project additionally requires **delivery leadership** — being an Owner or Manager on the record or on one above it. Having permission to view or edit is not enough on its own, and sponsors and project members are excluded. If a change is refused even though you have the right permission, this is usually why. See [Permissions](../user-guide/settings/permissions.mdx) for details.
