# Microsoft Teams

The Microsoft Teams connector stores an Entra app registration (tenant ID, client ID, and client secret) used to send chats and calendar events through Microsoft Graph. It does **not** sync data into Wayd.

Register a **dedicated** Entra application for Wayd Teams communication. It is separate from sign-in and from the [Entra people-sync](./entra.mdx) app registration.

- **Category:** Communication
- **Status:** Preview
- **Auth:** App registration (client secret)
- **Sync direction:** None

See the shared [integrations index](./index.mdx) for credentials, activation, and capability behavior.

## Setup

1. In the Entra admin portal, **register a new application** for Wayd Teams communication (not the people-sync or sign-in apps). Note the **Tenant ID** and **Application (client) ID**.
2. Under **Certificates & secrets**, create a **client secret**. Copy the value immediately — Entra only shows it once.
3. Grant the **Application permissions** listed in [Required permissions](#required-permissions) on Microsoft Graph, then select **Grant admin consent** for the tenant.
4. In Wayd, open **Settings → System → Connections**, choose **Microsoft Teams**, and enter the tenant ID, client ID, and secret.
5. Choose **Verify** on the create form. Wayd runs the hello-world Graph check (Teams message and all-day calendar event to your Wayd account email). After verification succeeds, save the connection. You can run **Test connection** again from the connection detail page at any time.

## Required permissions

Application permissions on Microsoft Graph (not Delegated), with admin consent:

| Permission | Why Wayd needs it |
|---|---|
| **User.Read.All** | Look up tenant users by email so Wayd can address Teams messages and calendar events to the right people. |
| **Chat.Create** | Open Teams chats when Wayd sends communication through this connection. |
| **ChatMessage.Send** | Send messages in Teams chats on behalf of this connection. |
| **Calendars.ReadWrite** | Create and update Outlook calendar events when Wayd sends scheduling-related communication. |

## Configuration options

| Option | Default | Notes |
|---|---|---|
| Tenant ID | — | Required. Non-empty, up to 64 characters. |
| Client ID | — | Required. Non-empty, up to 64 characters. |
| Client Secret | — | Required on create. Encrypted at rest; on edit, leave blank to keep the stored secret. Up to 512 characters. |

## Connection test behavior

**Verify** (create form) and **Test connection** (detail page) use the connection's own app registration (client credentials). They do not prompt for a second sign-in.

1. Resolve the signed-in user's Wayd account email.
2. Look up that address in the connection's tenant (`mail` or `userPrincipalName`).
3. Create a one-member Teams chat and post a short hello-world message.
4. Create an all-day calendar event for the current UTC date on that user's calendar.

If step 2 finds no user, the test returns an error and does not send a message or create an event. Wayd does not save a new Teams connection until this check succeeds.
